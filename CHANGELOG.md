# Changelog

## Unreleased

- Add "what is running now" series, all opt-in and additive (contract version stays 0): `metrics.per_session: true` makes `claude-sessions` export, for each live session (at most `metrics.max_sessions_per_profile`, default 50, per profile), `agent_session_state` (busy, idle, waiting, shell, other as fixed 0/1), `agent_session_waiting` (permission, input, dialog, sandbox, worker, goal, other; an exact map of the harness's own short labels, never free text), `agent_session_state_since_timestamp_seconds` and `agent_session_info` (entrypoint, tmux session name). The `session` label is the harness's session name made safe, usually a project folder name.
- Add the host-level `job-locks` source (`jobs.lock_dir`, `jobs.call_log`): `agent_job_running`, `agent_job_last_end_timestamp_seconds` and `agent_job_last_exit_code` per agent account, from the task runner's lock files and `/proc/locks` (the flock is never taken). Accounts without an exporter profile are covered.
- Add the `opencode-http` source (opencode profile `url`, loopback unless `allow_remote`): busy-session count from `GET /session/status` as `agent_sessions{state="active"}`.
- Add `--check-config` (load, validate, exit 0 or 1; no listener, no state writes) so a deployment can validate a config before a restart.
- `claude-sessions` counts a session as live only if its start time matches the file's `procStart` and its pid domain is this host's: a reused pid is no longer counted in `agent_sessions`, and a failed read of the sessions directory now drops the series and sets `agent_source_up` to 0 instead of serving the last list.

- Add the opt-in `zai-usage` source and the `zai` harness (`key_source: openclaw | opencode | zai-helper`, `quota: {zai_usage: true}`): z.ai GLM Coding Plan quota windows (`5h`, `7d`, `monthly` tool calls) and plan level, read with a key a local harness already holds. The exporter never asks for a key, never refreshes or writes anything, requests `api.z.ai` only, and reads a key shared by two profiles once. New gauges `agent_quota_used_calls` and `agent_quota_limit_calls`; `lite` joins the `plan` vocabulary. Contract version stays 0 (additive).
- Add the opt-in `codex-usage` source (`quota: {codex_usage: true}`): live Codex quota windows and credits from the ChatGPT backend, plus read-only reset-slot gauges `agent_quota_reset_credits_available` and `agent_quota_reset_credits_next_expiry_timestamp_seconds`. It never refreshes the token and never writes `auth.json`; the profile's `codex-rollouts` keeps its token counters and serves quota series only until `codex-usage` has a fresh reading.
- The scheduler offers free vendor-call slots oldest attempt first, so sources sharing a gate group take turns.
- Lower the `agy-usage` interval floor from 15 minutes to 2 minutes (the default stays 30 minutes); sources may now declare a shorter spacing between their vendor calls (`NetSpacer`), used by `agy-usage` (10 s) and `codex-usage` (5 s) so many accounts are all read within one interval.
- Read AgentKit's Claude status line cache for `/root/.claude` quota without vendor calls, with a per-profile cache path and optional OAuth fallback retaining its 15-minute floor.
