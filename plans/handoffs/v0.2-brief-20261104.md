## Findings, all read on real nodes today

**Codex (CLI 0.163.0).** `<CODEX_HOME>/sessions/YYYY/MM/DD/rollout-*.jsonl`: each `token_count` event has `payload.rate_limits` (`primary` and `secondary`, each `used_percent`, `window_minutes`, `resets_at`; `credits`: `has_credits`, `unlimited`, `balance`; `limit_id`) and `payload.info.total_token_usage`. Seen: 20 such events in one session. No client spawned, no token touched. The value is as of the profile's last turn.

**Credits flip.** One Codex workspace answered "Your workspace is out of credits" on all machines at 16:18, and worked again by 18:40. Windows looked fine throughout. Operators miss this, so the credits gauge matters. A gauge read from the last rollout will lag a flip, so its observed time has to be honest.

**agy (CLI 1.5.0).** `HOME=<profile> agy -p /usage --output-format json` returns `command.data.groups[].buckets[]` with `id` (`gemini-weekly`, `gemini-5h`, `3p-weekly`, `3p-5h`), `window`, `remaining_fraction`, `reset_time`, in 0 tokens and no model turn. Bare `/usage` in the TUI shows the same. The binary itself holds the private call, so this is the vendor's client making it. Fixture: `fixtures/agy/usage-command.json`.

**agy refresh, measured on one account by hash and mtime only.** The first call after the access token had expired rewrote the token file, with a new expiry an hour on. Two more calls right after changed nothing. So polling triggers the client's normal refresh about hourly. We didn't capture whether the refresh token rotated at that moment; a separate test on 10-31 found it doesn't. Keep the source off by default and document this.

**Accounts are copied across machines.** The same agy login sits on six machines, so one account must be read from one host only. Config has to allow that; don't dedupe by guessing.

**Rejected for agy.** CLIProxyAPI reaches the same data from its management UI, calling `retrieveUserQuotaSummary` itself with a spoofed client identity, and it would hold and refresh our tokens. cockpit-tools does much the same. Don't copy either.

**Claude stays on polling.** The maintainer: "Ok stay polling for cc then". `claude -p /usage --output-format json` works (0 tokens, 0.4 s) but returns an English text block with fewer windows and less precision. Don't add it.

**opencode.** `<data>/opencode/opencode.db`, `message.data` JSON has `role`, `providerID`, `modelID`, `cost`, `tokens{total,input,output,reasoning,cache}`, `time`. Several instances per machine, each with its own data dir, and not all under `~/.local/share`: service-managed ones sit under their own state path, so profiles come from config.

**Router.** Schema in `fixtures/router/router.schema.sql`. `providerConnections.data` mixes secrets with health fields, so only `json_extract` the listed ones. The DB was 927 MB on a production machine: read-only, incremental by `id`, no scans.

**Rollout facts for design.** v0.1 runs on six machines at about 8 MB. Scrapes go to VictoriaMetrics with relabel rules on the fleet side. The Claude quota trial has run for 8 hours with 0 429s.
